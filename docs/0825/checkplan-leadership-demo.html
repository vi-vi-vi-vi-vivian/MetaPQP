OpenJiuwen in MetaPQP

流程编排底座，不是决策大脑

当前只有Page 审计接入了 OpenJiuwen Workflow；Transition / Journey 已由 MetaPQP 的应用层运行器执行，但还没有包装成 OpenJiuwen Workflow。

OpenJiuwen Start Workflow / Connection · IO State · Session · Timeout · Async Invoke · Logging OpenJiuwen End

Workflow / DAG

用 Start、End、WorkflowComponent 和显式 Connection 固定节点顺序，避免流程由 Agent 自由规划。

IO State / Component

每个业务步骤包装成自定义 Component，通过输入 Schema 把同一份状态安全传给下一节点。

Session / Runtime

每个 Job 创建独立 Session，配置执行超时，通过异步 invoke 运行，并接入 OpenJiuwen 日志。

当前使用：Page Workflow 的确定性编排、状态传递、Session、超时与日志 当前边界：Journey Runner 已接入业务层，但尚未包装成 OpenJiuwen Workflow

Page 示例使用 awareness / product_landing 的演示上下文；三个 Plan 的输入、选择和执行批次来自当前代码实现。PageMapNode 当前主要由 Journey Runner用于起点校验和节点串联，单独的 Page CLI仍以 URL、PageSnapshot和PageContext为主。实线表示运行时数据或配置输入；虚线表示规则引用或跨层关联。
